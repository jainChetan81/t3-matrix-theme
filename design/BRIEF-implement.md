# Brief: build the Matrix theme for T3 Code (final implementation)

You are the implementer. Work only inside `~/Codebase/t3-matrix-theme` on this VPS. Do not commit or push, do not publish or select themes in T3 (`t3 theme set`, `~/.t3/userdata` are off limits), do not touch the Chrome on port 9222, never stop anything on port 20128, never blanket-kill processes. You may use subagents for side checks (e.g. an independent review of your CSS), but finish the build yourself.

## Goal
A green "digital rain" theme for T3 Code (desktop/web app for chatting with coding agents) that is (1) clearly Matrix, (2) soothing to read all day, (3) cheap to render. The user rejected the last build: "way too many matrices, looks bad, performance is bad"; wants better chat boxes, contrast, colours, layout polish. Their reference look: `design/rounds/reference-page.png` (https://chetan-examples.vercel.app/matrix, a canvas page that costs ~200 ms main thread per 5 s). The over-dense rejected build: `design/rounds/build1-too-dense.png`. Claude Design explorations: `design/rounds/r2-*.png`, kit in `design/claude-design-kit/` (README explains effects; the user liked the "Possessed" direction's ideas: ❯ prompt + block caret, CRT-ish code panes, subtle glitch, rain dimming while typing).

## Inputs
- `src/theme.css`, `src/colors.json`, `src/rain.svg` (1000x650 tile, vertical-text columns, bright head + fading trail), `src/spinner.svg`, `build.py` (assembles `matrix.json`, enforces limits). Run `python3 -I build.py`.
- Design spec from a scout: `design/spec/colors.json` (61 roles, soft mint text #c6dbcf on #060c0a ≈ 13.6:1, accent #0affa0 for small things only) and `design/spec/components.css` (component CSS). Its rain opacities (.12–.16) are probably too faint — the user's first-round complaint was "where is the rain?". Aim for rain that is clearly visible in the margins (roughly .25–.35, brighter heads) but never under text.
- Perf findings: `design/perf/recommended/` (+ bench tooling `design/perf/*.py`, written for a Mac headless Chrome; adapt paths). Measured facts:
  - Transform animation of ::before/::after margin layers with steps() is the cheapest technique: ~0.3 ms main thread per 5 s when the app is idle (compositor-only). SVG-internal animation or background-position animation cost 100–220 ms per 5 s (repaint/raster each step) — do not use.
  - When the page renders main frames for other reasons, Chrome re-styles every element with a running CSS animation on each frame (~0.1–1 ms each). So minimise the number of infinitely running animations: rain (≤ 2 layers in conversation, 1 on the new-thread screen), blink caret only while the composer is empty, glitch must run a bounded number of times (e.g. once on load / `animation-iteration-count: 1`), sheen only while `[data-slot="composer-host"][aria-busy="true"]`. No filters/drop-shadows on many elements, no large blurred shadows behind text, no text-shadow on body text, no animated text-shadow.
- Real T3 DOM facts (verified in the live app):
  - Stable hooks: `[data-workspace-area="conversation"]` (non-scrolling container; its children have transparent backgrounds; scroller is `.messages-timeline-scroll` inside), `[data-workspace-area="home"]` (new-thread screen), `[data-slot="sidebar-inner"]`, `[data-thread-item]` (li) whose child `[role="button"]` is the row card and carries `aria-current="page"` when active, `[data-slot="project-monogram"]` (contains an svg tile), `[data-chat-header]`, title text at `[data-chat-header] [data-slot="workspace-breadcrumb-text"]` (3 matches: breadcrumb parts), `[data-timeline-row-kind]` = message|event|turn-fold, `[data-message-role="user"|"assistant"]`, `[data-user-message-bubble]`, `.chat-markdown`, `.chat-markdown-codeblock`, `[data-slot="composer-host"]` (aria-busy true/false), `.composer-tiptap` (ProseMirror contenteditable; empty = `<p><br class="ProseMirror-trailingBreak"></p>`), `[data-thread-terminal-drawer]`, `[data-slot=tooltip-popup|menu-popup|popover-popup|dialog-popup|button|input|switch|select-trigger|scroll-area-thumb]`, `svg.lucide`.
  - Composer: the editor's grandparent (`:has(> * > .composer-tiptap)`, a `relative flow-root` div) also contains the placeholder as a sibling `div.pointer-events-none.absolute.inset-0`. The prompt glyph must sit on that grandparent and both editor text and placeholder must shift right, or the glyph overlaps the placeholder (this bug was seen live). Current working rules for that are in `src/theme.css`.
  - Reading column `.chat-content-lane` max-width 736 px, centred; conversation was 1256 px wide at a 1512 px window.
- Theme limits: CSS ≤ 20,000 chars, file ≤ 32 KB, url() only data:/#id, no @import, no image-set(), no backslashes (build.py checks). Colour roles listed in `src/colors.json`.
